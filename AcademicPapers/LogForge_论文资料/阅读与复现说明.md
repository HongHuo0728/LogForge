# LogForge 论文与复现资料

论文题名：**LogForge：HLG 至 Apple Log 转换的数学原理、源码实现与验证**。

正式阅读文件位于本目录的上一级：`LogForge_源码解析与数学论证_学术论文.pdf`。

## 研究范围

固定提交为 `6b43a93fbd4d1457ff20b4c99a030c0e398f520a`，版本为 1.2.1，构建号 26927B。正文共 24 章，含中英文摘要、数学模型与推导、实现机制、测试与性能讨论、两个附录和参考文献。字数、页数、图表数量、PDF SHA-256 以 `制作与验证统计.json` 为准。中文汉字数按 U+4E00—U+9FFF 统计，正文计入摘要、标题和图表说明，不把英文字符和公式长度当作中文汉字数。

## 文件用途

- `论文正文.md`：完整可编辑原稿；`@figure` 等标记由排版程序展开。
- `LogForge_技术论文.tex`：LaTeX 编辑源文件，与 `figures` 中的矢量 PDF 组成项目。它不是独立的单文件 LaTeX 文档。
- `figures`：18 幅插图的 SVG、PDF 与 PNG，以及编号公式的 SVG。
- `全仓库源码清单.json` / `.tsv`：102 个版本受控文件的路径、用途、行数、字节数和 SHA-256；JSON 另含结构定位索引。
- `LogForge_6b43a93_源码快照.zip`：由 `git archive` 生成的固定提交快照，保留原项目与第三方许可文件。
- `本次回归测试.xml`：本次 CTest 的完整 JUnit 记录。
- `evidence`：本次持续处理报告、CTest 日志、仓库历史基准及验证记录。
- `图表目录.json`：论文插图编号及中文说明。
- `版式检查`：PDF 页面渲染、联系表和结构检查结果，仅用于成品复核。

## 验证结论

本次实际执行 Release 构建成功。24 项 CTest 中 23 项通过，`media_pipeline` 失败。失败位置是 `tests/integration.py` 第 154 行的旧输入准入断言，与 1.2.1 放宽准入的实现发生冲突。论文同时分析了明确标为 BT.709 的输入仍可能被按 BT.2020 解释的风险。该测试脚本中失败断言之后的场景不能声称已通过。

240 帧 3840×2160、120 fps 素材的持续测试通过；“120 fps”是输入素材帧率，不是转码实时吞吐。精确耗时、峰值内存和抽样误差保留在原始 JSON 中。本文没有重新运行商业编辑器导入认证或完整相机实拍实验。

## 排版与复现

本次使用 Python 的 ReportLab 排版，Matplotlib 与 SVG 生成矢量公式、科学曲线和架构图，中文采用嵌入字体；PDF 通过 Poppler 渲染检查。`build_paper.py` 中的仓库路径当前为 `D:/LogForge`，字体路径使用 Windows 的 SimSun、SimHei 与 Times New Roman。重新生成前需准备同一提交及相应构建测试证据。

所需 Python 包：`reportlab`、`numpy`、`matplotlib`、`svglib`、`pymupdf`、`Pillow`。在本目录执行 `python build_paper.py` 可重新导出 PDF；运行 `python check_math.py` 可检查数学排版语法。`verify_pdf.py` 使用 `版式检查/page-*.png` 生成总览，并检查文字边界、替代字符及未展开指令。

本次已尝试内置 LaTeX 编译器，其返回基础环境错误 `Unable to find standard directories for platform`。因此交付的 PDF 由上述本地矢量排版流程生成，LaTeX 文件保留为可编辑源稿，未声称通过 LaTeX 编译。若用外部 XeLaTeX 编译，需保留相邻的 `figures` 文件夹及中文宏包。

数学结论以论文中列出的前提为限；有限测试、仓库历史记录与源码推导在正文中分别标识。源码索引覆盖全部版本受控文件，不意味着第三方 JSON 库和生成的 PTX 已获得逐行形式化验证。
